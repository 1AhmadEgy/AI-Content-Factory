AI CONTENT FACTORY — REPOSITORY CONTRACT

Repositories own durable data access and hide Room/PostgreSQL/HTTP details.

RULES
- Interfaces are domain/application-facing; implementations are infrastructure/data.
- UI never calls DAOs directly.
- Domain never depends on Room, SQL, Retrofit or provider SDKs.
- Reads return persisted source-of-truth state.
- Multi-record writes use transactions.
- Missing entities use stable NOT_FOUND errors.
- Updates define concurrency/lost-update behavior.
- Deletes define reference/cascade behavior.
- Idempotent operations remain idempotent.
- Storage exceptions map to AppError.

EXAMPLE
interface ProjectRepository { fun observeProjects():Flow<List<Project>>; suspend fun getProject(id:String):Result<Project>; suspend fun createProject(project:Project):Result<Project>; suspend fun updateProject(project:Project):Result<Project>; suspend fun deleteProject(id:String):Result<Unit> }

ANDROID
Room is local durable storage. BACKEND
PostgreSQL is server durable storage. Sync is above repository boundaries.

ACCEPTANCE
[ ] No UI→DAO [ ] No domain→Room [ ] Transactions [ ] Error mapping [ ] Concurrency policy [ ] Tests
